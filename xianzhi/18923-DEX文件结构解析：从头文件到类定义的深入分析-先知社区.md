# Dex基本结构

# 文件介绍

**DEX** 文件是 “**Dalvik Executable**” 的缩写，即 **Dalvik 可执行文件**。它是 Android 操作系统的核心组成部分之一，专门为 Android 平台设计，用于存储和执行应用程序代码。优点是比class文件体积小、真内存少、加载速度快、堆栈加载速度快、类查找快等，更适合在手机使用。在这些结构中的u4不是指的占用4个字节，而是指它们是uleb128类型（占用1~5个字节）的数据。

简单来说，当开发者用 Java 或 Kotlin 编写一个 Android 应用时，这些代码最终不会以标准的 Java 字节码（.class 文件）形式运行在用户的手机上。相反，它们会被编译和优化成 DEX 格式，然后打包到 APK (Android Package) 文件中。Android 系统通过其运行时环境（ART 或早期的 Dalvik）来解释和执行 DEX 文件中的指令。

​

dex文件的生成：`javac test.java`，`dx --dex -output=./text.dex test.class`

样例代码：

```
public class HelloWorld2 {
    int a = 0;
    static String b = "HelloDalvik";
    public int getNumber(int i, int j) {
        int e = 3;
        return e + i + j;
    }
    public static void main(String[] args) {
        int c = 1;
        int d = 2;
        HelloWorld2 helloWorld = new HelloWorld2();
        String sayNumber = String.valueOf(helloWorld.getNumber(c, d));
        System.out.println("HelloDex!" + sayNumber);
    }
}
```

# 文件结构

|  |  |
| --- | --- |
| Dex Header | 文件头 |
| String索引表 | header→偏移→字符串表(字节偏移数组→ULEB128转String) |
| Type索引表 | heaser→偏移→通过下标索引字符串表 |
| Proto索引表 | header→偏移→结构体数组→解析[返回类型、参数]等 |
| Field索引表 | header→偏移→结构体数组→解析[成员变量所属类、类型、名字]等 |
| Method索引表 | header→偏移→结构体数组→解析[方法的所属类、原型、名字]等 |
| Class定义表 | header→偏移→结构体数组→解析[方法的所属类、原型、名字]等 |
| 数据区 |  |
| Map块 | header→偏移→结构体数组→解析[各个映射块的地址偏移、大小]等 |

```
struct DexFile {
    /* directly-mapped "opt" header */
    const DexOptHeader* pOptHeader;

    /* pointers to directly-mapped structs and arrays in base DEX */
    const DexHeader*    pHeader;	//DEX 文件头，记录了一些当前文件的信息以及其他数据结构在文件中的偏移量
    const DexStringId*  pStringIds;	//数组,元素类型为string_id_item,存储字符串相关的信息
    const DexTypeId*    pTypeIds;	//数组,存储类型相关的信息
    const DexFieldId*   pFieldIds;	//数组,存储成员变量信息,包括变量名和类型等
    const DexMethodId*  pMethodIds;	//数组,存储成员函数信息包括函数名 参数和返回值类型
    const DexProtoId*   pProtoIds;	//数组,函数原型数据索引，记录了方法声明的字符串，返回类型和参数列表
    const DexClassDef*  pClassDefs;	//数组,存储类的信息
    const DexLink*      pLinkData;	//Dex文件重要的数据内容都存在data区域内,一些数据结构会通过如 xx_off这样的成员变量只想文件的某个位置,从该位置开始,存储了对应的数据结构的内容,而xx_off的位置一般落在data区域内

    /*
     * These are mapped out of the "auxillary" section, and may not be
     * included in the file.
     */
    const DexClassLookup* pClassLookup;
    const void*         pRegisterMapPool;       // RegisterMapClassPool

    /* points to start of DEX file data */
    const u1*           baseAddr;

    /* track memory overhead for auxillary structures */
    int                 overhead;

    /* additional app-specific data structures associated with the DEX */
    //void*               auxData;
};
```

## dex文件头

DEX的文件头的数据结构如下

```
/*
* Direct-mapped "header_item" struct.
*/
struct DexHeader {
    u1  magic[8];       //取值必须是字符串 "dex
035\0" 或者字节byte数组 {0x64 0x65 0x78 0x0a 0x30 0x33 0x35 0x00}，用来识别dex这种文件的，它可以判断当前的dex文件是否有效，目前，dex的魔数固定为dex.035。8个字节
    u4  checksum;       //文件内容的校验和,不包括magic和自己,主要用于检查文件是否损坏，4个字节
    u1  signature[kSHA1DigestLen];      //签名信息,不包括 magic\checksum和自己，把整个dex文件用SHA-1签名得到的一个值，20个字节
    u4  fileSize;       //整个文件的大小,包括所有的内容，4个字节
    u4  headerSize;     //默认是0x70个字节，表示DexHeader头结构的大小，4个字节
    u4  endianTag;      //大小端标签，标准.dex文件为小端，此项一般固定为0x12345678常量
    u4  linkSize;       //链接数据的大小,当多个class文件被编译到一个dex文件是，他们会用到link_size和link_off，通常为0
    u4  linkOff;        //链接数据的偏移值,当多个class文件被编译到一个dex文件是，他们会用到link_size和link_off，通常为0
    u4  mapOff;         //map item的偏移地址，其实就是dex文件最后一部分内容，该item属于data区里的内容，值要大于等于dataOff的大小，
    u4  stringIdsSize;      //DEX中用到的所有字符串内容的大小
    u4  stringIdsOff;       //DEX中用到的所有字符串内容的偏移量
    //所有被选中的都是DexStringId这种数据结构的内容，DexStringId代表的是字符串的位置偏移，每个DexStringId占用4个字节，也就是说它里面存的还不是真正的字符串，它们只是存储了真正字符串的偏移位置
    u4  typeIdsSize;        //DEX中类型数据结构的大小
    u4  typeIdsOff;         //DEX中类型数据结构的偏移值
    u4  protoIdsSize;       //DEX中的元数据信息数据结构的大小
    u4  protoIdsOff;        //DEX中的元数据信息数据结构的偏移值
    u4  fieldIdsSize;       //DEX中字段信息数据结构的大小
    u4  fieldIdsOff;        //DEX中字段信息数据结构的偏移值
    u4  methodIdsSize;      //DEX中方法信息数据结构的大小
    u4  methodIdsOff;       //DEX中方法信息数据结构的偏移值
    u4  classDefsSize;      //DEX中的类信息数据结构的大小
    u4  classDefsOff;       //DEX中的类信息数据结构的偏移值
    u4  dataSize;           //DEX中数据区域的结构信息的大小
    u4  dataOff;            //DEX中数据区域的结构信息的偏移值
};
```

## dex\_string\_ids

dex文件头之后是DexStringids，一个字符串常量池，存储了DEX文件中使用的所有字符串，文件头中的 string\_ids\_off 和 string\_ids\_size 指示了该段的位置和条目数量。每个条目是一个偏移量，指向数据段中实际的字符串数据。

};

这里有一个问题，字符串明明是8个字节，为什么选中了10个呢？因为每个字符串以 **ULEB128** 编码存储（leb128编码是一种变长编码，每个字节采用７位来表达原来的数据，最高位用来表示是否有后继字节。若第一个 Byte 的最高位为 1 ，则表示还需要下一个 Byte 来描述 ，直至最后一个 Byte 的最高位为 0 。每个 Byte 的其余 Bit 用来表示数据）。第一个08指定的是后面8个字节为具体数据，最后一个空字符0表示的是字符串的结尾。

## dex\_proto\_ids

`dex_proto_ids`段本身是一个数组，其大小由文件头中的 `proto_ids_size` 字段指定，起始偏移量由 `proto_ids_off` 字段指定。数组中的每个元素都是一个 `proto_id_item` 结构体。`proto_ids` 段的核心作用是将方法的签名抽象出来，并在整个 DEX 文件中进行复用。当多个方法具有相同的返回类型和参数类型列表时，它们可以引用同一个 `proto_id_item`。这有助于减小文件大小。解析 `proto_ids` 段是理解类结构和方法调用的重要一步。通过解析 `proto_id_item`，我们可以确定方法的返回类型和参数类型，这对于静态分析、反编译和理解程序逻辑至关重要。

```
/*
 * Direct-mapped "proto_id_item".
 */
struct DexProtoId {
    u4  shortyIdx;          /* index into stringIds for shorty descriptor */
    u4  returnTypeIdx;      /* index into typeIds list for return type */
    u4  parametersOff;      /* file offset to type_list for parameter types */
};
```

```
shortyIdx (uint):
这是一个无符号整数，表示方法“短描述符”（shorty descriptor）在 字符串索引段 (string_ids) 中的索引。
短描述符是一个紧凑的字符串，用单个字符表示基本类型，用 'L' 表示引用类型。例如：
V: void
I: int
Z: boolean
I: int[]
L: 任何引用类型（如类或接口）
短描述符的格式是：方法的返回类型的短描述符，后面跟着所有参数类型的短描述符（按顺序）。例如，一个方法 int foo(String s, boolean b) 的短描述符可能是 "ILSZ" (返回类型 int 'I', 参数类型 String 'L', boolean 'Z')。
这个字段主要用于快速比较方法签名，而不需要解析完整的类型描述符。

returnTypeIdx (uint):
这是一个无符号整数，表示方法的返回类型在 类型索引段 (type_ids) 中的索引。
通过这个索引，可以去 type_ids 段找到对应的 type_id_item，再通过 type_id_item 中的索引去 字符串索引段 (string_ids) 找到完整的返回类型描述符（例如 Ljava/lang/String; 或 I）。

parametersOff (uint):
这是一个无符号整数，表示方法参数类型列表 (type_list) 在数据段 (data section) 中的偏移量。
type_list 是一个单独的数据结构，它包含一个 size 字段（表示参数数量）和一个 type_item 数组。
type_item 数组中的每个元素是一个 ushort，表示一个参数类型在 类型索引段 (type_ids) 中的索引。这些索引按照参数在方法签名中出现的顺序排列。
如果方法没有参数，则 parameters_off 的值为 0。

    DexTypeItem list[1];    /* entries */
};

/*
 * Direct-mapped "type_item".
 */
struct DexTypeItem {
    u2  typeIdx;            /* index into typeIds */
};
```

## dex\_field\_ids

DEX 文件中的`field_ids` 段本身是一个数组，其大小由文件头中的 `field_ids_size` 字段指定，起始偏移量由 `field_ids_off` 字段指定。数组中的每个元素都是一个 `field_id_item` 结构体。`field_ids` 段的作用是集中管理 DEX 文件中所有引用的字段信息。无论是类的成员变量、方法中访问的字段，还是其他地方引用的字段，都会在这里有一个对应的 `field_id_item` 条目。通过解析 `field_ids` 段，我们可以获取每个字段的所属类、类型和名称。这对于理解程序的数据结构、进行字段访问分析以及逆向工程都非常重要。

```
/*
 * Direct-mapped "field_id_item".
 */
struct DexFieldId {
    u2  classIdx;           /* index into typeIds list for defining class */
    u2  typeIdx;            /* index into typeIds for field type */
    u4  nameIdx;            /* index into stringIds for field name */
};
```

```
class_idx (ushort):
这是一个无符号短整数，表示字段所属的类在 类型索引段 (type_ids) 中的索引。
通过这个索引，可以去 type_ids 段找到对应的 type_id_item，再通过 type_id_item 中的索引去 字符串索引段 (string_ids) 找到字段所属类的完整类型描述符（例如 Lcom/example/MyClass;）。

type_idx (ushort):
这是一个无符号短整数，表示字段的类型在 类型索引段 (type_ids) 中的索引。
通过这个索引，可以去 type_ids 段找到对应的 type_id_item，再通过 type_id_item 中的索引去 字符串索引段 (string_ids) 找到字段类型的完整描述符（例如 I 表示 int，Ljava/lang/String; 表示 String）。

name_idx (uint):
这是一个无符号整数，表示字段的名称在 字符串索引段 (string_ids) 中的索引。
通过这个索引，可以去 string_ids 段找到字段的实际名称字符串。
```

## dex\_method\_ids

`method_ids` 段本身是一个数组，其大小由文件头中的 `method_ids_size` 字段指定，起始偏移量由 `method_ids_off` 字段指定。数组中的每个元素都是一个 `method_id_item` 结构体。`method_ids` 段的作用是集中管理 DEX 文件中所有引用的方法信息。无论是类中定义的方法、调用其他类的方法，还是其他地方引用的方法，都会在这里有一个对应的 `method_id_item` 条目。通过解析 `method_ids` 段，我们可以获取每个方法的所属类、方法签名以及方法名称。这对于理解程序的控制流程、进行方法调用分析、构建调用图以及进行逆向工程都非常重要。需要注意的是，`method_ids` 段只提供了方法的引用信息。方法的实际字节码、寄存器信息、调试信息等是存储在数据段中的 `code_item` 结构体里，并通过类定义段 (`class_defs`) 中的方法信息来关联。

```
/*
 * Direct-mapped "method_id_item".
 */
struct DexMethodId {
    u2  classIdx;           /* index into typeIds list for defining class */
    u2  protoIdx;           /* index into protoIds for method prototype */
    u4  nameIdx;            /* index into stringIds for method name */
};
```

```
class_idx (ushort):
这是一个无符号短整数，表示方法所属的类在 类型索引段 (type_ids) 中的索引。

## dex\_class\_defs

`class_defs` 段本身是一个数组，其大小由文件头中的 `class_defs_size` 字段指定，起始偏移量由 `class_defs_off` 字段指定。数组中的每个元素都是一个 `class_def_item` 结构体。结合 `class_data_item` 的解析，我们可以进一步获取类的所有字段和方法的详细信息，包括它们的类型、名称、访问标志以及方法的实际字节码。总结来说，`class_defs` 段存储了 DEX 文件中每个定义的类的元数据和指向其详细数据的偏移量。它是理解 DEX 文件中类结构和内容的入口点。

```
/*
 * Direct-mapped "class_def_item".
 */
struct DexClassDef {
    u4  classIdx;           /* index into typeIds for this class */
    u4  accessFlags;
    u4  superclassIdx;      /* index into typeIds for superclass */
    u4  interfacesOff;      /* file offset to DexTypeList */
    u4  sourceFileIdx;      /* index into stringIds for source file name */
    u4  annotationsOff;     /* file offset to annotations_directory_item */
    u4  classDataOff;       /* file offset to class_data_item */
    u4  staticValuesOff;    /* file offset to DexEncodedArray */
};
```

```
class_idx (uint):
这是一个无符号整数，表示当前类在 类型索引段 (type_ids) 中的索引。
这是识别当前类自身的关键。通过这个索引，可以去 type_ids 段找到对应的 type_id_item，再通过 type_id_item 中的索引去 字符串索引段 (string_ids) 找到类的完整类型描述符（例如 Lcom/example/MyClass;）。

access_flags (uint):
这是一个无符号整数，表示类的访问标志。这些标志定义了类的可见性、特性等，例如：
ACC_PUBLIC (0x0001): 类是公共的。
ACC_FINAL (0x0010): 类是 final 的，不能被继承。
ACC_SUPER (0x0020): 指示编译器生成的代码是否需要特殊处理（通常为真）。
ACC_INTERFACE (0x0200): 类是一个接口。
ACC_ABSTRACT (0x0400): 类是抽象的。
ACC_ANNOTATION (0x2000): 类是一个注解类型。
ACC_ENUM (0x4000): 类是一个枚举类型。
这些标志可以通过按位与操作来解析。
其他值可见https://source.android.google.cn/docs/core/runtime/dex-format?hl=zh-cn#access-flags

superclass_idx (uint):
这是一个无符号整数，表示当前类的父类在 类型索引段 (type_ids) 中的索引。
如果当前类是 java.lang.Object，则这个字段的值为 NO_INDEX (0xffffffff)，因为它是根类没有父类。
通过这个索引，可以找到父类的类型描述符。

interfaces_off (uint):
这是一个无符号整数，表示当前类实现的接口列表 (type_list) 在 数据段 (data section) 中的偏移量。
如果类没有实现任何接口，则该值为 0。
type_list 的结构与方法参数列表的 type_list 相同，包含一个 size 字段和 type_item 数组，每个 type_item 是一个接口在 type_ids 段中的索引。
/*
 * Direct-mapped "type_list".
 */
struct DexTypeList {
    u4  size;               /* #of entries in list */
    DexTypeItem list[1];    /* entries */
};
/*
 * Direct-mapped "type_item".
 */
struct DexTypeItem {
    u2  typeIdx;            /* index into typeIds */
};
    
    
source_file_idx (uint):
这是一个无符号整数，表示与当前类关联的源文件名在 字符串索引段 (string_ids) 中的索引。
这个信息通常用于调试。如果编译时没有保留源文件信息，则该值为 NO_INDEX。

annotations_off (uint):
这是一个无符号整数，表示当前类的注解数据在 数据段 (data section) 中的偏移量。
如果类没有注解，则该值为 0。
这个偏移量指向一个 annotations_directory_item 结构，其中包含了类、字段和方法的注解信息。
/*
 * Direct-mapped "annotations_directory_item".
 */
struct DexAnnotationsDirectoryItem {
    u4  classAnnotationsOff;  /* offset to DexAnnotationSetItem */
    u4  fieldsSize;           /* count of DexFieldAnnotationsItem */
    u4  methodsSize;          /* count of DexMethodAnnotationsItem */
    u4  parametersSize;       /* count of DexParameterAnnotationsItem */
    /* followed by DexFieldAnnotationsItem[fieldsSize] */
    /* followed by DexMethodAnnotationsItem[methodsSize] */
    /* followed by DexParameterAnnotationsItem[parametersSize] */
};

static_values_off (uint):
这是一个无符号整数，表示当前类的静态字段的初始值列表在 数据段 (data section) 中的偏移量。
如果类没有带初始值的静态字段，则该值为 0。
这个偏移量指向一个 encoded_array_item 结构，其中包含了静态字段的初始值。
/*
 * Direct-mapped "encoded_array".
 *
 * NOTE: this structure is byte-aligned.
 */
struct DexEncodedArray {
    u1  array[1];                   /* data in encoded_array format */
};
```

```
class_data_off (uint):
这是一个无符号整数，表示当前类的类数据 (class_data_item) 在 数据段 (data section) 中的偏移量。
如果类没有静态字段、实例字段、直接方法或虚方法，则该值为 0。
当 class_data_off 不为 0 时，它指向数据段中的一个 class_data_item 结构体，其格式如下（注意其中使用了变长编码 ULEB128 和 SLEB128）：
struct class_data_item{
    static_fields_size;
    instance_fields_size;
    direct_methods_size;
    virtual_methods_size;
		static_fields;
		instance_fields;
		direct_methods;
		virtual_methods;
}
static_fields_size (uint, ULEB128): 
静态字段(类变量)的数量。

instance_fields_size (uint, ULEB128): 
实例字段的数量,成员变量或非静态字段，它们属于类的每一个特定的实例（对象）。

direct_methods_size (uint, ULEB128): 
直接方法（包括构造函数、静态方法、私有方法）的数量，这些方法不能被子类重写。

virtual_methods_size (uint, ULEB128): 虚方法（非静态、非私有、非构造函数的方法）的数量，虚方法是可以被子类重写的非静态、非私有、非构造函数的方法。它们通常对应于 Java 中的实例方法（Instance Methods），但不包括私有方法和构造函数。

static_fields:
定义的静态字段；以一系列编码元素的形式表示。这些字段必须按 field_idx 以升序进行排序。
encoded_field 数组: 包含 static_fields_size 个静态字段的定义,以一系列编码元素的形式表示。这些字段必须按 field_idx 以升序进行排序。

instance_fields:
定义的实例字段；以一系列编码元素的形式表示。这些字段必须按 field_idx 以升序进行排序。
encoded_field 数组: 包含 instance_fields_size 个实例字段的定义，以一系列编码元素的形式表示。这些字段必须按 field_idx 以升序进行排序。

Struct encoded_field{
    field_idx_diff
    access_flags
}
field_idx_diff (uint):
此字段标识（包括名称和描述符）的 field_ids 列表中的索引；它会表示为与列表中前一个元素的索引之间的差值。列表中第一个元素的索引则直接表示出来。

direct_methods:
含 direct_methods_size 个直接方法(static、private 或构造函数的任何一个)的定义，定义的直接方法，使用encoded_method格式描述这些方法，，以一系列编码元素的形式表示。这些方法必须按 method_idx 以升序进行排序。。

virtual_methods:
含virtual_methods_size个虚拟方法(非 static、private 或构造函数)的定义，定义的虚拟方法，使用encoded_method格式描述这些方法，以一系列编码元素的形式表示。此列表不得包括继承方法，除非被此项所表示的类覆盖。这些方法必须按method_idx 以升序进行排序。虚拟方法的 method_idx 不得与任何直接方法相同。

encoded_method 数组
Struct encoded_method{
    method_idx_diff;
    access_flags;
    code_off;
}
method_idx_diff(U2):
此方法标识（包括名称和描述符）的 method_ids 列表中的索引；它会表示为与列表中前一个元素的索引之间的差值。列表中第一个元素的索引则直接表示出来。

code_off (uint):
从文件开头到此方法的代码结构的偏移量；如果此方法是 abstract 或 native，则该值为 0。偏移量应该是到 data 区段中某个位置的偏移量。数据格式由下文的“code_item”指定。
encoded_field结构包含字段在field_ids段中的索引差值和访问标志。encoded_method结构包含方法在method_ids段中的索引差值、访问标志以及指向方法代码 (code_item) 的偏移量。

/*
 * Direct-mapped "code_item".
 *
 * The "catches" table is used when throwing an exception,
 * "debugInfo" is used when displaying an exception stack trace or
 * debugging. An offset of zero indicates that there are no entries.
 */
struct DexCode {
    u2  registersSize;
    u2  insSize;
    u2  outsSize;
    u2  triesSize;
    u4  debugInfoOff;       /* file offset to debug info stream */
    u4  insnsSize;          /* size of the insns array, in u2 units */
    u2  insns[1];
    /* followed by optional u2 padding */
    /* followed by try_item[triesSize] */
    /* followed by uleb128 handlersSize */
    /* followed by catch_handler_item[handlersSize] */
};
在 DEX 文件中，code_item 结构体包含了方法的实际可执行代码（字节码）以及与代码执行相关的元数据，例如寄存器信息、异常处理信息和调试信息。每个非抽象、非 native 的方法都会在数据段中有一个对应的 code_item。
registers_size (ushort):
这是一个无符号短整数，表示该方法执行所需的寄存器总数。Dalvik/ART 虚拟机使用基于寄存器而非基于栈的架构，这里的寄存器数量包括了参数寄存器和局部变量寄存器。

ins_size (ushort):
这是一个无符号短整数，表示该方法的入参寄存器数量。这些寄存器用于传递方法的参数。

outs_size (ushort):
这是一个无符号短整数，表示该方法在调用其他方法时可能需要的出参寄存器最大数量。

tries_size (ushort):
这是一个无符号短整数，表示与该方法代码关联的 try-catch 块的数量。如果为 0，则表示没有异常处理信息。

debug_info_off (uint):
这是一个无符号整数，表示方法的调试信息（如源代码行号、局部变量信息）在数据段中的偏移量。如果方法没有调试信息，则该值为 0。这个偏移量指向一个 debug_info_item 结构体。

insns_size (uint):
这是一个无符号整数，表示方法字节码指令序列 (insns 数组) 的 16 位单元（ushort）数量。

insns (ushort[]):
这是方法的实际字节码指令序列。它是一个 ushort 数组，包含 insns_size 个 16 位指令单元。Dalvik/ART 字节码指令的格式和操作码是解析这部分数据的关键。
    
Padding (可选):
如果 insns_size 是奇数，并且 tries_size 大于 0，那么在 insns 数组后面会有 2 个字节的填充 (padding)，以确保后续的 try_item 数组是 4 字节对齐的。

try_item 数组 (如果 tries_size > 0):
这是一个 try_item 结构体数组，数量为 tries_size。每个 try_item 描述一个 try 块的范围和对应的异常处理器列表。

try_item 结构包含：
start_addr (uint): try 块开始的指令地址（相对于方法第一条指令）。
insn_count (ushort): try 块包含的指令数量。
handler_off (ushort): 指向对应的异常处理器列表 (handlers_item) 的偏移量（相对于紧随 try_item 数组后的 handlers_item 结构体）。

handlers_item 结构体 (如果 tries_size > 0):
这是一个变长结构，包含了所有的异常处理器列表。它的起始位置紧随在 try_item 数组（及可能的 padding）之后。
它以一个 ULEB128 值 size 开头，表示异常处理器列表的数量。
后面跟着 catch_handler_list，其中包含 size 个 catch_handler_item。
catch_handler_item 描述了一个或多个异常类型及其处理代码的起始地址。它使用 SLEB128 编码异常类型索引和处理地址。

code_item 的作用
code_item 是 DEX 文件中实现方法逻辑的核心数据结构。它包含了虚拟机执行方法所需的全部信息：
字节码 (insns): 定义了方法的具体操作序列。
寄存器信息: 指导虚拟机如何分配和使用寄存器来存储变量和执行计算。
异常处理信息 (try_item, handlers_item): 定义了代码执行过程中可能抛出和捕获异常的范围及处理逻辑。
调试信息 (debug_info_off): 允许调试器在源代码级别跟踪方法执行。

code_item 的偏移量存储在类定义段 (class_defs) 的 class_data_item 中的 encoded_method 结构体里。通过解析 class_defs -> class_data_item -> encoded_method，可以找到每个方法的 code_item 并对其进行进一步的分析，例如反汇编字节码、分析控制流等。
总结来说，code_item 存储了方法的字节码、寄存器使用信息、异常处理信息和调试信息，是 DEX 文件中实现方法可执行逻辑的关键数据结构。
```

```
package org.hao;

import org.jf.dexlib2.DexFileFactory;
import org.jf.dexlib2.Opcodes;
import org.jf.dexlib2.iface.ClassDef;
import org.jf.dexlib2.iface.DexFile;
import org.jf.dexlib2.iface.Field;
import org.jf.dexlib2.iface.Method;

import java.io.File;
import java.io.IOException;
import java.lang.reflect.Modifier;

/**
 * @author 63179
 */
public class DexParser {

    public static void main(String[] args) {
        // TODO: 在这里修改为您的 .dex 文件路径。
        // 如果文件位于项目根目录,可以直接写文件名,例如 "classes.dex"。
        // 否则,请使用绝对路径,例如 "C:/Users/YourUser/Desktop/classes.dex"。
        String dexFilePath = "src/main/resources/classes.dex";

        File dexFile = new File(dexFilePath);
        if (!dexFile.exists()) {
            System.err.println("错误: 文件不存在 -> " + dexFilePath);
            System.err.println("请确保文件路径正确,并且文件位于指定位置。");
            return;
        }

        try {
            // 使用 DexFileFactory 加载 DEX 文件
            // 第二个参数是 API level，对于简单的读取操作，可以指定一个通用的值
            DexFile loadedDexFile = DexFileFactory.loadDexFile(dexFile, Opcodes.forApi(19));

            System.out.println("成功解析 DEX 文件: " + dexFile.getName());
            System.out.println("========================================
");

            // 遍历 DEX 文件中的所有类定义
            for (ClassDef classDef : loadedDexFile.getClasses()) {
                // 打印类名
                // Lcom/example/MyClass; -> com.example.MyClass
                String className = classDef.getType().replace('/', '.').substring(1, classDef.getType().length() - 1);
                System.out.println("[类] " + className);

                // 遍历并打印类中的所有字段 (变量)
                for (Field field : classDef.getFields()) {
                    // 获取并格式化访问标志 (e.g., public, static, final)
                    String access = decodeAccessFlags(field.getAccessFlags());

                    String fieldType = decodeType(field.getType());
                    String fieldName = field.getName();
                    System.out.println("  - [字段] " + access + " " + fieldType + " " + fieldName);
                }

                // 遍历类中的所有方法
                for (Method method : classDef.getMethods()) {
                    // 构建方法签名
                    StringBuilder methodSignature = new StringBuilder();
                    methodSignature.append("  - [方法] ").append(method.getName()).append("(");

                    // 拼接参数类型
                    boolean firstParam = true;
                    for (CharSequence paramType : method.getParameterTypes()) {
                        if (!firstParam) {
                            methodSignature.append(", ");
                        }
                        methodSignature.append(decodeType(paramType.toString()));
                        firstParam = false;
                    }
                    methodSignature.append("): ");

                    // 拼接返回类型
                    methodSignature.append(decodeType(method.getReturnType()));

                    System.out.println(methodSignature.toString());
                }
                System.out.println(); // 在每个类之后添加一个空行
            }

        } catch (IOException e) {
            System.err.println("解析 DEX 文件时出错:");
            e.printStackTrace();
        }
    }

    /**
     * 将 DEX 的访问标志整数转换为 Java 可读的修饰符字符串
     * @param flags DEX 访问标志
     * @return Java 修饰符字符串
     */
    private static String decodeAccessFlags(int flags) {
        // java.lang.reflect.Modifier 类提供了方便的工具来解析这些标志
        // 尽管 DEX 的标志和 Java 的标志不完全一一对应,但对于通用修饰符是兼容的。
        return Modifier.toString(flags);
    }

    /**
     * 将 DEX 的内部类型描述符转换为 Java 可读的类型名称
     * 例如：Ljava/lang/String; -> java.lang.String
     * I -> int
     * V -> void
     * @param typeDescriptor DEX 类型描述符
     * @return Java 类型名称
     */
    private static String decodeType(String typeDescriptor) {
        switch (typeDescriptor) {
            case "V": return "void";
            case "Z": return "boolean";
            case "B": return "byte";
            case "S": return "short";
            case "C": return "char";
            case "I": return "int";
            case "J": return "long";
            case "F": return "float";
            case "D": return "double";
            default:
                if (typeDescriptor.startsWith("L") && typeDescriptor.endsWith(";")) {
                    return typeDescriptor.substring(1, typeDescriptor.length() - 1).replace('/', '.');
                }
                if (typeDescriptor.startsWith("[")) {
                    return decodeType(typeDescriptor.substring(1)) + "[]";
                }
                return typeDescriptor; // 未知类型
        }
    }
}
