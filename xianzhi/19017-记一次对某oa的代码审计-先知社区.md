## `ExtensionlessUrlHandler`

ASP.NET 中的一个 HTTP 处理程序，主要用于处理无扩展名的 URL。

### 处理无扩展名 URL

允许网站使用友好的 URL，而不需要显示文件扩展名：

```
text
传统 URL: http://example.com/products.aspx?id=123
友好 URL: http://example.com/products/123
```

### URL 路由支持

配合 NET 路由系统，实现 RESTful 风格的 URL：

```
text
GET  /api/users/123     -> 获取用户信息
POST /api/users         -> 创建用户
PUT  /api/users/123     -> 更新用户
DELETE /api/users/123   -> 删除用户
```

### 配置方式

在 web.config 中配置

IIS 7.0+ 配置：

```
xml
<system.webServer>
  <handlers>
    <add name="ExtensionlessUrlHandler-Integrated-4.0" 
         path="*." 
         verb="*" 
         type="System.Web.Handlers.TransferRequestHandler" 
         preCondition="integratedMode,runtimeVersionv4.0" />
  </handlers>
</system.webServer>
```

经典模式配置：

```
xml
<system.webServer>
  <handlers>
    <add name="ExtensionlessUrlHandler-ISAPI-4.0_32bit" 
         path="*." 
         verb="GET,HEAD,POST,DEBUG,PUT,DELETE,PATCH,OPTIONS" 
         modules="IsapiModule" 
         scriptProcessor="%windir%\Microsoft.NET\Framework\v4.0.30319\aspnet_isapi.dll" 
         preCondition="classicMode,runtimeVersionv4.0,bitness32" 
         responseBufferLimit="0" />
  </handlers>
</system.webServer>
```

## `JHSoft.Log.HttpModule`

是一个第三方或自定义的 HTTP 模块，用于在 ASP.NET 应用程序中处理日志记录功能。

主要处理HTTP 请求日志记录和错误日志记录。

HTTP 请求日志记录

* 记录所有进入应用程序的 HTTP 请求
* 捕获请求 URL、方法、参数等信息
* 记录响应时间和状态码

​

错误日志记录

* 捕获应用程序中的未处理异常
* 记录错误堆栈信息
* 提供错误通知机制

# 后台文件写入

**漏洞位置**：JHSoft.Web.Portal/EditMain.aspx 页面

**核心风险**：外部输入未受严格验证，导致恶意用户可控制文件写入路径及内容，存在持久化文件写入风险，甚至可实现远程代码执行 (RCE)​

**具体漏洞点**：

1. **add 参数处理不当**  
   接收的 add 参数仅简单将 "|" 替换为 "\"，未进行路径规范化校验及权限边界检查，允许直接传入绝对路径或跨目录的相对路径，可指向系统任意可写位置。
2. **id 参数验证缺失**  
   id 参数直接拼接至 "...Portal\Default" 路径后作为文件路径，未实施白名单验证，且未限制文件后缀名。攻击者可构造如 "id=1.aspx" 的恶意值，直接创建或覆盖 ASPX 可执行脚本文件。

**恶意利用方式**：

* 通过构造 id 参数（如 "id=webshell.aspx"），可在应用目录下写入包含恶意代码的 ASPX 文件
* 利用 add 参数指定系统其他可写目录（如网站根目录、临时文件夹等），实现跨目录文件写入
* 保存机制采用 StreamWriter (FilePath, append: false) 模式，若目标文件已存在则先执行 File.Delete (FilePath) 再覆盖写入，可直接替换现有文件

# XXE漏洞

发现代码未对 XmlDocument 禁用 DTD/外部实体解析，LoadXml 会在允许的框架版本/配置下解析外部实体，导致：外带请求（SSRF/DNSLOG 命中）、本地文件泄露（file://）、实体扩展拒绝服务（Billion Laughs）。

后续直接把节点值拼接进 SQL。

![image.png](images/20250928151031-38782624-9c3a-1.png)

变量初始化与读取 XML 数据

```

string text2 = string.Empty;
StreamReader streamReader = new StreamReader(base.Request.InputStream);
string xml = streamReader.ReadToEnd();
```

* 初始化两个字符串变量`text`和`text2`（命名不规范，影响可读性）
* 通过`StreamReader`从请求输入流中读取全部内容，保存为 XML 字符串
* 这里直接读取整个请求体作为 XML 数据，未做任何验证和过滤

XML 解析处理

```
XmlDocument xmlDocument = new XmlDocument();
xmlDocument.LoadXml(xml);
if (xmlDocument.DocumentElement != null)
{
    XmlNodeList childNodes = xmlDocument.DocumentElement.ChildNodes;
    for (int i = 0; i <= childNodes.Count - 1; i++)
    {
        text = text + childNodes.Item(i).Name + ",";
        text2 = text2 + "'" + childNodes.Item(i).InnerText + "',";
    }
}
```

* 使用`XmlDocument`加载并解析 XML 数据
* 遍历 XML 根节点的所有子节点，将节点名拼接至`text`（字段名），将节点文本内容拼接至`text2`（字段值）
* **风险点 1**：未禁用 XML 外部实体（XXE），可能导致 XXE 攻击，如读取服务器本地文件或发起内网请求
* **风险点 2**：直接使用节点文本内容，未做任何过滤处理

SQL 语句拼接

```
text += " AddrCode ";
text2 = string.Concat(text2, "'", Session["UserCode"], "'");
string strSql = "insert into AddressUser (" + text + ") values (" + text2 + ")";
```

* 在字段列表和值列表中分别添加`AddrCode`字段和当前用户编码（从 Session 获取）
* 直接拼接字段名和值，构建完整的 INSERT 语句
* **严重风险**：这里存在明显的 SQL 注入漏洞！因为直接将用户可控的 XML 节点名和节点值拼接进 SQL 语句，攻击者可通过构造特殊 XML 内容注入恶意 SQL 代码

```
        base.Response.End();
    }
}
```

## 漏洞复现：

1. 首先将路径中的`\\`替换为`/`，但传入的`/..../`因不含`\\`而保持原样；
2. 接着执行`../`替换为`/`的操作，然而`/..../`实际是`../`的变形形式（`....`可拆解为`..+..`），替换后路径被简化为`/../`；
3. 最后代码又将路径中的`/`替换回`\\`，最终形成`\\..\\`这一包含上级目录跳转的危险路径。
