## 与服务器验证密码进行破解

对一个需通过网络与服务器验证密码的二进制文件进行破解。首先通过 x64dbg 分析二进制文件的网络通信流程，包括初始化套接字、连接服务器、发送接收数据等，发现密码验证依赖服务器返回结果。随后找到可修改的关键指令位置，通过**补丁修改**使比较结果恒为真，最终生成无需服务器验证、输入任意密码都显示正确的破解二进制文件

```
#include <winsock2.h>
#include <windows.h>
#include <stdio.h>
#include <ws2tcpip.h>

void VerifyKey(char* Key, char* buffer) {

    char KeyValue[8] = "";
    WSADATA version;
    WSAStartup(MAKEWORD(2, 2), &version);
    SOCKET my_socket = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
    sockaddr_in my_address;
    my_address.sin_family = AF_INET;
    my_address.sin_addr.s_addr = inet_addr("127.0.0.1");
    my_address.sin_port = htons(8080);
    connect(my_socket, (SOCKADDR*)&my_address, sizeof(my_address));
    send(my_socket, Key, strlen(Key) + 1, 0);
    recv(my_socket, KeyValue, 8, 0);
    if (strcmp(KeyValue, "Valid
") == 0) {
        strcat(buffer, "[+] Correct Password");
    }
    else {
        strcat(buffer, "[-] Invalid Password");
    }
    closesocket(my_socket);
    WSACleanup();
}

int main(int argc, char* argv[]) {

    if (argc != 2) {
        printf("Help:
%s <10 character serial key>
", argv[0]);
    }

    else {
        int KeyLen = strlen(argv[1]);
        if ((KeyLen > 10 || KeyLen < 10)) {
            printf("[-] Invalid Key Length. Password must be of 10 characters
");
        }
        else {
            char buffer[21] = "";
            VerifyKey(argv[1], buffer);
            printf("%s", buffer);
            memset(buffer, 0, sizeof(buffer));
        }
    }

    return 0;
}

Hash,一般翻译做散列、杂凑,或音译为哈希,是把任意长度的输入(又叫做预映射pre-image)通过散列算法变换成固定长度的输出,该输出就是散列值。这种转换是一种压缩映射,也就是,散列值的空间通常远小于输入的空间,不同的输入可能会散列成相同的输出,所以不可能从散列值来确定唯一的输入值。简单的说就是一种将任意长度的消息压缩到某一固定长度的消息摘要的函数。

MD5 的压缩函数执行**64 轮迭代**，分为**4 组**（每组 16 轮），且输出为**128 位哈希值**（由 4 个 32 位寄存器拼接而成）

SHA-1 的压缩函数共执行**80 轮迭代**，并将这 80 轮分为**4 组**（每组 20 轮），但由于其输出为**160 位哈希值**（由 5个 32 位寄存器拼接而成）

什么是编码、解码?

编码:一般来说就是利用某种算法对原始内容进行处理,形成另一种数据的表现形式,并可以根据相关

算法再还原回来。

解码:使用编码算法的逆算法对经过编码的数据进行处理,还原出原始数据。

base系列编码算法常见的有base16、base32、base58、base64,它们出现的主要目的都是为了将一些  
特殊的、不可见的二进制数据经过编码后转化为可打印字符,以此使我们的数据能正确的、方便的  
在不同设备上显示和网络上传输。注意他们只是一个编码算法,并不是加密算法。

比如以前的邮件发送就只能发送可见字符,而像我们要传输一张图片的时候,因为一张图片的二进  
制信息不可能全是可见字符,这就导致了不能传送了。但我们可以把该图片的二进制信息经过base系  
列编码转化为可见字符,在传送后再解码就可以了。

然后,base系列编码算法是一种变长编码算法,如base64是将原数据的每三个字节变为四个字节,  
base32是将原数据的每五个字节变为八个字节,base16是将原数据的每一个字节变为两个字节,而  
base58是从256进制转到58进制,自然会使数据变长,因此他们的缺点就是会造成信息冗余,数据量

增大。

最后,base系列编码转换算法本质上是一种进制转换算法,如base64是将原数据转化为64进制,与此  
对应的base32、base16、base58就是将原数据转化为32进制,16进制与58进制。进制转换也是base58  
编码的用的转换算法,而base64、base32、base16因为码表大小是2的整数次方倍,转换方法就可以

使用更快捷的移动二进制位(切割bit位)的方法,那么其实我们base64、base32、base16也是可以使  
用进制转换的方法来进行(但是要处理按照切割bit位时会有的填充情况),只是使用通过移位的方  
式(切割bit位)不会产生大数的运算,使转换速度更快。这也是为什么一般都把base58与base64、  
base32、base16分开对待的原因。

那么码表的作用是什么呢?

就是将进制转化后的的每个权重数通过查表用一个字符来表示它,这就和我们16进制数中A、B、C、

D、E、F来表示10、11、12、13、14、15是一个道理。

切割bit位  
先将原数据变为其二进制bit位形式,然后根据转换的目标进制数选择对应的数量的bit位为一组对原  
始数据的bit位进行切割(如base64是64进制,那就选择6个bit位为一组,因为6个bit位能表示的最大

数正好是63)(二进制111111就是63，base32二进制11111就是31)(从0开始)。

注:base58不能用这种方法,因为58不是2的整数次方。

256进制。符串实际上就是256进制的数字组合,像我们平时看到的一串数据都是256进制,它的每  
一个字节表示一个权重位,大小就是一个字节的范围[0,255],如在密码学中就经常用libnum库的s2n()  
函数把一串字符按大端序变为它实际的进制数后再进行加密。

码表:123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghi jkmnopqrstuvwxyz

大小:58  
常用于URL,邮件文本,可见字符显示及产生 Bitcoin 的钱包地址

base58的码表比base64的少了6个,主要就是将一些歧义字符,如0(零)、0(大写字母0)、I

因为base58是58进制算法,而58不是2的整数次方,这就使我们编码base58不能使用效率更高的切割

base58check

另外,在base58基础之上还有一种base58check编码,一种常用在数字加密货币中的base58编码格式,  
它的特点就是在待编码数据的尾部增加了一个4字节的校验码。这个校验码是对待编码的数据进行  
sha256,然后取其前4字节。

当我们使用base58check编码时,在要使用这个编码的数据之前先会计算原始数据的sha256的前4字  
节是否和尾部的校验码相同,如果不同则表明有错误发生,那么这个base58check编码自然就是无效  
的了,这样就可以避免一些错误的发生。

## AES

高级加密标准(AES,Advanced Encryption Standard)为最常见的对称加密算法(微信小程序加密传输就  
是用这个加密算法的)。对称加密算法也就是加密和解密用相同的密钥,具体的加密流程如下

AES为分组密码,分组密码也就是把明文分成一组一组的,每组长度相等,每次加密一组数据,直到加密完整个明文。在AES标准规范中,分组长度只能是128位,也就是说,每个分组为16个字节(每个字节8位)。密钥的长度可以使用128位、192位或256位。密钥的长度不同,推荐加密轮数也不同,如下所示:

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **AES 版本** | **密钥长度（32位比特字）** | **分组长度（32位比特字）** | **加密轮数** | **实际密钥长度（位）** |
| AES-128 | 4 | 4 | 10 | 128 |
| AES-192 | 6 | 4 | 12 | 192 |
| AES-256 | 8 | 4 | 14 | 256 |

加密流程

**① 密钥扩展（Key Expansion）**

* 从一个初始密钥派生多个轮密钥（Round Keys）。
* 通过置换、S盒替换、轮常量异或等操作生成44个32位字（共176字节）。

**② 初始轮（Initial Round）**

**AddRoundKey**：明文与第一轮轮密钥逐字节异或。

**③ 主轮（9轮重复操作）**

每轮包含4步：

1. **SubBytes**：通过S盒（非线性替换表）进行字节替换。
2. **ShiftRows**：对状态矩阵的行循环左移（第0行不移，第1行移1字节，依此类推）。
3. **MixColumns**：列混合（矩阵乘法，扩散作用）。
4. **AddRoundKey**：与当前轮密钥异或。

**④ 最终轮（第10轮）**

* 省略MixColumns，仅执行：SubBytes → ShiftRows → AddRoundKey。

16轮Feistel网络，每轮操作（i=1到16）：

## rc4

rc4是一种序列密码也称流密码,它属于对称加密算法的一种。密钥长度是[1,256]个字节。  
特点:算法简单,运行速度快且密钥长度可变,范围:[1,256]个字节。

什么是序列密码?  
就是算法在密钥控制下产生的一种随机序列,然后使用这个随机序列去和明文依次异或得到密文。

什么是对称加密算法?

简单的来说就是加密密钥与解密密钥相同的密码算法。

加密算法

一、变量初始化  
定义两个大小为256的S盒和T盒、密钥及明文。Q(小写的k数组用于存放最后生成的异或流)

```
S = [0]*256
T = [0]*256

K = list (b"this is key! ! ! !")
keylen .= len (K)
k =< 0]*256
print ("key:", bytes (K))

p = list (b"this is Plaintext")
len = len (p)
print ("p:", bytes (p))
```

二、密钥初始化  
1、初始化s盒和T盒。

```
#初始化s盒和T盒
for i in range (256) :
S[i] =i
T[i] = K[i%keylen]
```

在逆向分析时，找到初始化s盒和T盒位置就可以知道密钥

2、使用存放密钥的T盒来打乱s盒。

```
#使用密钥打乱s盒
j = 0
for i in range (256) :
j=(j+S[i]+T[i]) %256
S[i], S[j] = S[j], S[i]
```

三、产生异或流  
使用经过密钥打乱的s盒来生成和明文长度一样的异或流。

```
#产生异或流
i =0
j =0
efor r in range(len) :#1en为明文的长度,k用于存放生成的异或流
i = (i+1) %256
j = (j+S[i]) %256
S[i], S[j] = S[j], S[i]
t = (S[i]+S[j]) %256
k[r] = S[t]
```

四、异或加密

将明文和刚刚生成的异或流依次异或,完成加密。

```
#异或加密
for i in range (len) :
p[i]^=k[i] #k是上面生成的密钥流
```

rc4是一个序列密码,从上面可以知道,这种加密算法对明文的加密只有最后的异或,又根据异或的  
性质,所以此类密码算法的加密过程和解密过程都是一样的,只要密钥相同产生的异或流就相同。

也就是对于序列密码只要我们得到了异或流就可以加密和解密了。

## rsa

rsa是一种非对称加密算法,它是基于大数分解的数学难题的加密算法。

什么是非对称加密算法?  
简单来说就是加密密钥与解密密钥不相同的加密算法,这也说明了它有两个密钥,一个公钥、一个  
私钥。

密钥生成  
RSA的算法涉及三个参数，n、e、d，其中n被称为模数，是两个大质数p、q的积，n的二进制表示时所占用的位数，就是所谓的密钥长度。e和d是一对相关的值，e可以任意取，但要求e与(p-1)x(q-1)互质；再选择d：要求(dxe-1)能被(p-1)x(q-1)整除。值e和d分别称为公共指数和私有指数。公钥是数对(n，e)，密钥是数对（n，d)。

公钥

![](images/20250819151641-744eff0c-7ccc-1.png)

私钥

![](images/20250819151641-747d321e-7ccc-1.png)

加密  
获得信息接收者的公开密钥(n，e)。  
(1)将明文分组：m=m0，ml，m2，…，mk-1。使得mi<n(i=0，1，…，k-1)。  
(2）对每一组明文用一下公式做加密变换ci-E(mi)-mie(mod n)。  
(3）得到密文c=c0，cl，c2，…，ck-1。

![](images/20250819151641-749b34c6-7ccc-1.png)

解密  
(1)对每一密文做解密变换mi=D(ci)=cd(modn）。  
(2）合并分组得到的明文m-mO，ml，m2，……mk一1。  
知道公钥可以得到获取私钥的途径，但这取决于将模数因式分解成组成它的质数。如果选择了足够长的密钥，这样基本上不可能获取私钥。RSA实验室建议：普通公司密钥1024位就已足够。对极其重要的资料，就用双倍的大小的2048位。日常使用768位就能满足要求。  
密钥长度增加时会影响加密/密的速度，所以这里有一个权衡。将模数加倍将使得使用公钥的操作时间大概增加为原来的4倍，而用私钥加密/解密所需的时间增加为原来的8倍。进一步说，当模数加倍时，生成密钥的时间平均将增加为原来的16倍。

如果想要实现解密,一个简单的方法是将轮密钥rki 逆序后再执行一次32 轮的加密运算  
即将密文投入加密函数,并且第0轮使用rk31 作为轮密钥,第i 轮使用 rk31-i 作为轮密钥,  
最后获得的结果便是加密前的密文

* TEA：加密轮数固定（通常 32 轮），汇编中可见 “sum += delta” 和 “y += (z<<4 + key[0]) ^ ...” 的对称操作，密钥是 4 个 32 位整数；
* XTEA：轮数可自定义，密钥访问方式不同（key[sum&3]和key[(sum>>11)&3]），反汇编中可见 “sum参与密钥索引计算”；
* XXTEA：支持多块数据加密（n为数据块数），代码中有 “for (p=0; p<n-1; p++)” 的多轮循环，且MX宏的表达式更复杂（含z>>5^y<<2等混合操作）。  
  同时补充 “破解实例”：若逆向中发现某段加密函数符合 XXTEA 的特征，如何提取密钥（通过内存 dump 密钥数组）、如何用工具（如 IDA 的 Hex-Rays 插件）反编译出key的值，再用 XXTEA 解密脚本验证。

若反汇编中密钥索引是key[sum&3]或key[(sum>>11)&3]（如mov ecx, key[ecx+sum&3]），是 XTEA；若密钥索引固定为key[0]~key[3]（如mov edx, key[0]），是 TEA；若有 “多数据块循环”（for (p=0; p<n-1; p++)），是 XXTEA。

XOR 的特征是xor指令在循环中高频出现（如xor al, [key+esi]）；TEA 系列必有 “sum += delta” 和 “移位 + 异或混合运算”（如(z<<4) ^ (z>>5)）；SM4 则有 “S 盒查表操作”（反汇编中会有mov al, [sbox+eax]，S 盒是固定数组0xd6,0x90,0xe9...）。
